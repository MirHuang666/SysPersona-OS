## 一句话设问

**一件事做完之后，系统怎么自己证明它真的闭了环？**

## 设计思想

前几版把能力一块块接上了（启动、记忆、压缩、跨机），但"做完了没有"一直是靠人记得去看。
这一版不再加能力，只补**证据与对账**：每件事都要留下一条能被机器读到的记录，缺记录就是没做完。

所以它叫「全链路运行闭环」——不是功能名，是**验收口径的名字**。

## 做了什么

- **异常台账**：失败不再只躺在日志里，进可查询的账；
- **断链与孤儿**：谁指向了不存在的东西（文档/脚本/路径），自己报出来，而不是等人撞见；
- **覆盖检查**：可检索范围与真实文件对账，缺失与未入索引都算红；
- **唤醒分工**：心跳、空闲唤醒、程序自检三件事各管一段，不再互相盖掉；
- **守护自刷新**：脚本改了以后守护怎么知道、怎么换新代码；
- **注入通道归位**：回执与投递走同一条通道，避免"发出去了但没人证明它到过"；
- **托盘状态栏 + 中文自检项**：人一眼能看到红的是哪条；
- 当天改过的脚本同步进 `tools/`；
- 补 `CHANGELOG` 条目——**发布记录不能只存在于提交信息里**。

## 证据

本版的证据以仓库内 `CHANGELOG` 与各文档的实测段为准；本页不重复数字（复述即违规）。
逐条判据见 `docs/RELEASING.md` 与 `设定\文档\自检清单.md`。
