## 范围

这一版改的不是功能，是交付形态：停止自研客户端，把记忆层接到开源壳上。

前面四个大版都在造自己的壳：加载、组装、路由、执行、归档，五件事都要自己兜。结论是——**壳是最不值钱的那层**：它天天在变（Electron、UI、登录、模型路由），而记忆层几乎不变。继续自研壳，等于用有限的精力去追一个一直在动的东西。

所以这一版做了三件套的分工，边界写死：

| 件 | 谁 | 约定 |
|---|---|---|
| 壳 | **Hermes Agent 官方版**（Electron + Python，本地 SQLite + FTS5，**自带 JSON-RPC/WS 网关**） | 只读不托管；记忆仍是纯文件，两边随时可拆 |
| 脑 | **DeepSeek 官方** `deepseek-flash`（1M 窗口） | 判断型任务不降级给免费小模型 |
| 检索 | 本地索引（不出门） | embedding 与 rerank 都在本机 |

## 为什么壳必须是官方版

不是体验偏好，是**有没有接口**：

| 能力 | 社区版 | 官方版 |
|---|---|---|
| 读上下文水位 | ✗ | ✓ `session.context_breakdown` |
| 取整段原文 | ✗ | ✓ `session.history` |
| 触发压缩 | ✗ | ✓ `session.compress` |
| 会话空闲判定 | ✗ | ✓ `session.active_list` |
| 外部派发 | ✗ | ✓ `prompt.submit` / `hermes -z` |

社区版只剩一个能点的界面——没有请求入口，就只能靠人来回点、靠到处乱开会话去凑上下文。这不是"功能少一点"，是**它压根不能被程序驱动**。

## 两个细节是设计，不是配置

- **路径**：`C:\hermes-mem` 用目录联接（Junction）指向中文长路径。为什么不用真路径？小模型的分词会把 `AI会话检索记录` 读成 `AI 会话检索记录`（多一个空格）→ `File not found`。绕开它的缺陷，比要求它别犯错便宜。
- **工具面**：`platform_toolsets` 白名单把 31 组裁到 11 组。上下文预算是产品约束：多留一组工具，就少留一段记忆。

## 落盘与压缩的规矩（修订版补充）

**先落盘，再压缩；只认实测降幅。**

水位到 300K → 导出原文 + sha256 回读校验 → 调压缩 → 再比对前后水位。

**坑**：`session.compress` 会假报成功——实测 2 条消息的会话返回 `status: "compressed"`，但 `removed: 0`、前后 token 一致、水位没降。按状态字段判成败，就会在该压的时候误报"压好了"。所以只认数字：没降就记 `unconfirmed`。

壳自带的自动压缩降为保底（0.8 ≈ 838K），只在主动压缩失效时兜底。

## 证据

- 官方版水位实测：15,811 / 1,048,576；底座开销 16.7K token（系统提示 + 工具定义 + 子代理），与聊过多少无关。
- 派发往返：新会话 15.5 s、续接 12.0 s，纯文本返回。
- 内存：官方壳全套 ≈ 0.68 GB，旧壳 ≈ 2.07 GB。
- 本机显存 2 GB，本地模型不可行（最小可用模型就要 16.2 GB）——这条不改，写清楚。

## 边界

- **数据出本地**：大脑在云端，发给它的都离机；上云前必须过 `mask_secrets.py`，这条**尚未接进调用链**——仍是最大的未闭合项。
- **免费档限流**：免费模型只作备用，RPM/TPM 打满即 429，批量活不要压在上面。
- **壳升级会打回原形**：官方版更新会重写 `config.yaml` 与 `SOUL.md`。`SOUL.md` 已改为由 `配置/内核/kernel.json` 幂等重生成（`persona_soul.py --check` 自检），`config.yaml` 的 provider 段仍需重放。
- **登录态**：官方版不依赖网页会话登录，这条旧问题随换壳消失。
- 不含：登录态持久化；脱敏只实现未接线。
