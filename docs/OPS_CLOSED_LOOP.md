# 运维闭环（v6.6 的核心）

> 一句话：**写下去的东西，别人一定找得到；找到了，人一定能处理；处理完一定退场。**
> 这三段缺任何一段，就叫「断链」；压根没人知道它存在，就叫「孤儿」。

## 一、两个词（先分清）

| 词 | 定义 | 症状 | 谁去发现 |
|---|---|---|---|
| **断链** | 没有闭环：有头没尾，或中间少一段 | 能写不能读、能读不能处理、处理完不退场 | 待办视图 / 全局同步 / 唤醒修复 |
| **孤儿** | 别人根本不知道它存在 | 文件躺在角落、没人提过、搜不到 | 孤儿文档检查 / 可检索覆盖检查 |

## 二、闭环四段

| 段 | 标准 | 机器检查 |
|---|---|---|
| ① 写 | 有唯一落点（`文档管理规范` 的落点表） | — |
| ② 读 | 出现在**人实际会走的那条路**上（入口 / 待办 / 自检 / 托盘） | `docmap`、`coverage` |
| ③ 处理 | 有明确动作与执行者，并写下「为什么」 | `todo`（待办 / 待批申请 / 异常三行） |
| ④ 退场 | 解决后删除或归档，别人仍能查到痕迹 | `persona_anomaly.py done`（删文件 + 历史留一行） |

## 三、异常台账（跨机求助 / 审批）

- **一条一个文件**：`ops/<机器id>/异常/<id>.json`（待处理）
- **批过的**搬到 `ops/<机器id>/归档/异常-已批/`，**处理完直接删**（要留痕用 `--keep`）
- **别人读得到**：`python 脚本/persona_anomaly.py pending --all`，待办视图里也分「本机 / 别机」两栏
- **远程批**：`python 脚本/persona_anomaly.py approve <id>`（只追加一条批准记录，不改原记录）
- **不刷屏**：同一原因**每天最多提醒一次**（24 小时）；24 小时内复发到第 3 次转「静默 12 小时」，只挂列表不再唤醒
- **不会永远忽略**：抑制有有效期，过期照常提醒

## 四、两种唤醒，各管一段

| 唤醒 | 干什么 | 不干什么 |
|---|---|---|
| **空闲唤醒**（心跳） | 读待办 + 意图池，有活挑一件、没活回「无新任务」，做完写日志 | 不修环境异常 |
| **自检异常唤醒** | 修异常（含统一发版），把托盘修绿 | 不挑活干 |

## 五、覆盖检查（防孤儿）

`python 脚本/persona_coverage.py` 四类一起看：

1. 文档：每份都在入口地图里；
2. 脚本：每个都在 `文档/索引-脚本.md` 里（该索引由 `persona_script_index.py` 自动生成，覆盖 `脚本/` 与 `ops/` 下的 `.py`）；
3. 索引：`index/L1.jsonl` 指向的文件都真实存在；
4. 会话与归档：`archive/` 的会话目录能在索引里找到；`sessions/<机器id>/` 里不能有比索引更新的文件。

四项任一不过 → 自检 `coverage` 判红，直接列出孤儿名字。

## 六、更新也要跟着闭环

改完脚本不能只「自己觉得对」：
`bump` → `manifest --record` → `publish` → 各机 `persona_sync.py --apply` → 自检转绿。
守护自身的代码更新由 `selfrefresh` 负责：**脚本比守护新 + 距上次刷新 ≥ 1 小时**才换进程，
所以改脚本不会把守护拖进无限重启。
