# 架构总览（现行）

> 本文是**对外口径**的架构页；库里入口页 `README.md` 指向本文，冲突时以本文 + 代码为准。
> 最后更新：2026-11-16（本机实测：**只跑插件形态**，托盘为可选）。

## 一、两种形态

| 形态 | 谁在跑 | 适合 | 现状 |
|---|---|---|---|
| **托盘形态（独立）** | 托盘进程 + 守护 + 计划任务 | 机器常年开机、要"看得见状态"的桌面 | **2026-11-16 起本机不用**（人：「托盘退休了，现在换插件了」）；代码与文档保留，可随时恢复 |
| **插件形态（寄生）** | DSH 客户端 + `@syspersona/persona-core` 插件 | 人就在客户端里干活、要"消息能进来、自检自己跑" | **现行**：登录由启动项拉起客户端，插件随客户端加载 |

两种形态**共用同一套库**（`D:\<电脑名>-文件\AI会话检索记录\`），所以切换形态不迁移数据。

## 二、三层分工（这是能换客户端的原因）

| 层 | 放什么 | 依赖客户端吗 |
|---|---|---|
| **内核层** | 库结构、闭环（发版/台账/索引/覆盖检查）、异常台账、脚本 | **不依赖**：客户端换了它照样跑 |
| **接线层** | 我们唯一的插件 `@syspersona/persona-core`：收件箱投递 + 自检定时 + 随机沉默唤醒 | 依赖，但只碰 3 个稳定入口（`agents.list/followup`、`setInterval`、文件） |
| **借用层** | 第三方插件（IM、花费、桌面自动化、任务板…） | 依赖，但都在"边缘"；坏了不影响闭环 |

**一句话**：功能不依赖客户端，接口才依赖；换客户端只重写接线层那几百行。

## 三、现行启动链（本机）

```
登录
 └─ 启动项 SysPersona-DSH.lnk  →  DSH 客户端
      └─ 加载 @syspersona/persona-core（junction 指向库内 配置\客户端\plugins\persona-core）
           ├─ 收件箱：ops\<机器>\<通道>\inject-request.jsonl → agent.followup → inject-ack.jsonl
           ├─ 自检定时：每 120 秒跑 脚本\persona_selfcheck.py --once（带锁）
           └─ 空闲唤醒：随机间隔 + 概率沉默（掷空不花钱），掷中才写 wake 请求
```

计划任务 `SysPersona-Daemon` **已禁用**（不再是必需路径）；要用托盘形态时再启用。

## 四、库的闭环（在哪都能查）

| 环节 | 命令 | 产物 |
|---|---|---|
| 待办 | `persona_todo.py add/list` | 本机 `待办\inbox\<机器>.md`（节点合并进 `文档\BACKLOG.md`） |
| 自检 | `persona_selfcheck.py --once` | `ops\<机器>\selfcheck.json`（红项带原因） |
| 版本 | `persona_ver.py status` / `publish` | `配置\版本.json`（全局只读，需许可） |
| 覆盖 | `persona_coverage.py` | 文档/脚本/索引/会话四类孤儿 |
| 插件发布 | `persona_plugin_release.py --bump patch --note "…"` | 版本 + 三份同步 + 台账 |

## 五、不做的边界

- 不自己写 IM 协议、不自己维护模型价格表、不自己写桌面自动化 —— 用现成的（见 `docs/TRAY-CURRENT.md` §四）；
- 不为了"整齐"把功能搬进插件；插件只做接线；
- 删记忆、改人格、改内核配置：必须人点头。
